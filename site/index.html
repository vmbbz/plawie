Straight answers

Before you install.

Is Plawie native or PRoot?

Native-first. Android owns the primary mobile Gateway lifecycle and device bridges. PRoot is preserved only as an explicit user-demand rollback path.

Does everything stay on my phone?

No blanket claim like that would be honest. The Gateway and app controls run locally, and local models can stay on-device. If you select a cloud provider, the data needed for that request is sent to that provider under its terms.

Why does first setup download components?

OpenClaw moves quickly. Plawie downloads the current official Gateway during fresh setup instead of bundling a stale copy, then resolves optional mobile runtimes through the install channel. Successful components leave receipts so setup can resume without wasting data.

Can I use a local model?

Yes, on supported Android hardware and for models that fit the device. You can also select supported cloud providers for larger or different workloads.

Will every desktop OpenClaw skill run on Android?

No. Mobile-compatible skills can run through native tools or verified Android dependency packs. The Skills page shows readiness, required configuration, and genuine platform blockers instead of pretending all desktop binaries are available.

Can Plawie spend from my wallet by itself?

No. Wallet actions are designed to stop at a visible approval containing the amount, network, recipient, reason, and expiry, followed by device authentication before signing.

When is the Google Play release?

The Play listing is being prepared alongside final release and policy acceptance. Until a real store URL exists, GitHub Releases remains the public sideload channel. The Play build will use Play-approved delivery for executable modules.
